# 화면 설계 — 감사 로그(`/admin/audit`), 대시보드 로그인 실패 추이, 설정 보강

Plan 5 Task 12 산출물. `frontend-design` 스킬로 `docs/design/direction.md`(고성능 HMI 관제 콘솔)와 `screens/logs.md`(같은 색인을 읽는 로그 조회)를 감사 화면에 적용했고, 대시보드 카드는 `dataviz` 스킬, 문구는 `design:ux-copy`(해요체, `web/src/copy/ko.ts`의 `audit`·`dashboard.loginFailures`·`settings.service`), React 구조는 `vercel-react-best-practices`를 따랐습니다. 창 폭은 W41대로 1920·1280·1024·800·640(높이 600·800)에서 확인했고 휴대폰 배치는 만들지 않습니다.

## 1. 일

- **누가:** 로그인한 MCP 개발자와 Admin, 두 채널 모두(`view_audit`). 내보내기는 `export_logs`.
- **첫째 일:** "누가 언제 어느 채널에서 무엇을 바꿨나"(관리 작업, §6.4 #8)와 "누가 언제 로그인을 시도했나"(§4.1.5)를 같은 표에서 훑는 것.
- **둘째 일:** 거부·실패·오류만 골라 보기(결과 칩), 사람 한 명으로 좁히기(행위자), 그 조건 그대로 내보내기.
- 상태는 URL 하나(W34): `kind`·`range`·`from`·`to`·`users`·`result`·`channel`·`q`.

## 2. 한 가지 대담함: 결과 열

로그 화면의 대담함은 히스토그램이었습니다. 감사 화면은 표 자체가 일이므로 **결과 열**에 힘을 둡니다. 성공은 흐린 잉크의 체크 아이콘 + "성공", 실패·거부·오류는 위험 색 아이콘 + 진한 글자. 색만으로 구분하지 않습니다(아이콘 모양 4가지 ✓ ⊗ ⦸ △ + 글자). 나머지(탭·칩·표)는 로그 화면과 같은 중립 헤어라인입니다.

| 흔한 기본값 | 이 화면의 선택 |
|---|---|
| 감사 로그 = 로그 화면 + 카테고리 고정 | 종류 탭(관리 작업·로그인·전체) + 종류마다 다른 결과 칩(관리 작업: 성공·거부·오류, 로그인: 성공·실패, 전체: 넷 다) |
| 대상(target)을 JSON 그대로 | `키=값, 키=값` 요약 120자(중첩 값은 압축 JSON), 로그인은 Windows 계정(로컬 채널, Plan 4) + 브라우저 앞 60자 |
| 결과를 색 배지로 | 아이콘 + 글자, 위험 색은 아이콘에만 |
| 기본 기간 = 로그 화면처럼 최근 1시간 | **최근 7일**: 관리 작업은 드물어 1시간이면 대개 빈 화면 |

## 3. 배치

```
감사 로그                                                                 ← h1
[관리 작업] [로그인] [전체]                                                  ← Radix Tabs(line), URL kind
┌ 필터 ─────────────────────────────────────────────────────────────────────┐
│ 기간 [최근 1시간][오늘][어제][최근 7일]  시작 시각 [ … ] 끝 시각 [ … ] [적용] │ ← TimeRangePicker 재사용
│ 결과 (✓성공)(⦸거부)(△오류)          채널 [모든 채널][로컬][원격]             │ ← aria-pressed 칩 / ToggleGroup
│ [행위자 ▾]  키워드 [            ]                [조건 지우기] [내보내기 ▾]   │ ← UserFilter(건수: /api/logs/users?cat=…)
└───────────────────────────────────────────────────────────────────────────┘
┌ 표(자기 틀에서만 스크롤, 높이 = 남은 뷰포트) ───────────────────────────────┐
│ 시각 | 행위자 | 채널 | IP | 작업 | 대상 | 결과                              │ ← VirtualTable, 행 32px
└───────────────────────────────────────────────────────────────────────────┘
```

- 열 순서는 계획 그대로: 시각(13.5rem, 밀리초) · 행위자(13rem) · 채널(8rem, `copy.channel`) · IP(9rem, mono) · 작업(14.5rem, mono — `service_start_type_apply`가 잘리지 않는 폭) · 대상(나머지) · 결과(6.5rem). 표 최소 폭 76rem.
- 행을 누르면(또는 Enter) 로그 화면의 상세 대화상자(`LogDetail`): 사실 + 원문 JSON, "이 사용자로 거르기". 감사 화면에는 세션 필터가 없어 세션 버튼은 빠집니다.

### 폭별 배치(실측, 실제 백엔드)

| 폭 | 내비 | 필터 | 표 |
|---|---|---|---|
| 1920 | 사이드바 | 세 줄(기간 / 결과·채널 / 행위자·키워드·내보내기) | 가로 스크롤 없음, 높이 398px(×800) |
| 1280 | 사이드바 | 같음 | 표 틀 안에서만 가로 스크롤(작업·대상·결과는 오른쪽) |
| 1024 | 사이드바 | 같음 | 틀 안 가로 스크롤 |
| 800 | 아이콘 레일 | 시작·끝 시각이 한 줄, [적용]은 다음 줄 | 틀 안 가로 스크롤, 높이 283px(×600) |
| 640 | 아이콘 레일 | 결과 칩·채널이 한 줄씩 접힘 | 틀 안 가로 스크롤 |

모든 폭에서 `document.documentElement.scrollWidth − innerWidth = −15`(스크롤 막대 폭, 페이지 가로 스크롤 없음).

## 4. 대시보드 "로그인 실패 추이" 카드 (dataviz)

- **형태:** 변화량(24시간, 시간당 1칸) → 작은 누적 막대. 큰 숫자 타일은 쓰지 않음(합계는 범례 줄 안의 글자).
- **색:** 새 색 없음. 웹 로그인(`auth`) = 보안 묶음 색, 원격 데스크톱(`session`) = 접속 묶음 색. Task 11에서 검증기를 통과한 `GROUP_STACK`의 이웃(보안↔접속)이라 쌓았을 때 CVD에서도 구분됩니다.
- **표식:** `LogHistogram compact`(막대 높이 40px, 축은 양 끝만, 최댓값 선 없음). `onSelect`가 없으면 그림(`role=img`, 탭 정지 없음, 끌기 없음)이고 마우스를 올리면 칸별 툴팁만 나옵니다. 툴팁 이름은 `names`로 "웹 로그인/원격 데스크톱".
- **범례:** 두 계열이므로 항상 표시하고 계열마다 건수를 글자로 붙임 — 막대가 숫자의 유일한 통로가 아님. 그 옆에 "모두 N건".
- **이름:** `chartLabel(total)` = "최근 24시간 시간대별 로그인 실패, 모두 N건".
- **조회:** `useLogHistogram({from: 올림−24h, to: 올림, cat:[auth,session], event:[login,logon_failed], outcome:[fail]}, "cat", 24)`. 대시보드를 열어 둔 동안 5분마다 창이 앞으로 갑니다.
- **링크:** "로그에서 보기" → `/admin/logs`에 같은 `from`/`to`(빠른 범위가 아님)와 조건. 실제로 눌러 두 줄(잘못된 코드 두 번)이 나오는 것을 확인했습니다.
- **상태:** 불러오는 중 = 같은 높이의 정적 블록(`role=status`), 0건 = `empty`, 오류 = `error`(`role=alert`), `view_logs`가 없으면 이유 문장.

## 5. 설정 보강

- **보존 확인 대화상자:** 삭제 건수 표 아래에 `retentionDeleteEvents(n)`(삭제할 파일이 있고 `delete_events`가 숫자일 때만, null = 색인이 아직 셀 수 없음)과 `retentionRunsSoon`(항상).
- **Windows 서비스(`ServiceSection`):** 부팅 시작 유형 선택 바로 아래 `dl`("Windows 서비스" + 상태). 설치 안 됨 → 묶음(`bundle`)이거나 서비스로 실행 중이면 `notInstalled`, 아니면 `devMode`(F20). 설치됨 → `current(start_type)`, 다르면 경고 아이콘 + `mismatch`. 시작 유형을 바꿔 저장하면 상태를 다시 읽습니다. Plan 3의 `startTypeNote`는 지웠습니다.
- `mismatch` 문구는 "서비스가 다시 시작할 때 이 설정으로 맞춰요"로 고쳤습니다: 서버는 값이 **바뀔 때**와 서비스 시작 때만 SCM에 적용하므로(W25) "다시 저장하면"은 사실이 아니었습니다.

## 6. 움직임

없음. 로그·감사 영역 규칙(§6.5) 그대로: 탭·칩·토글·행·막대에 전환 없음, 검색 이동마다 `viewTransition: false`, 자리 표시는 정적 블록(`data-anim` 없음 — 테스트). 공용 대화상자·메뉴의 기존 움직임만 남습니다(reduced-motion 존중).

## 7. 키보드 경로

탭 목록(←/→, Radix) → 기간 토글 → 시작·끝 시각 → 적용 → 결과 칩(Tab, Space/Enter로 켜고 끔, `aria-pressed`) → 채널 토글 → 행위자(팝오버, cmdk 목록) → 키워드 → 조건 지우기 → 내보내기(메뉴) → 표(행 하나만 탭 순서, ↑/↓, Enter로 상세, Escape로 닫으면 그 행으로 포커스 복귀). 대시보드 카드는 링크 하나만 탭 정지.

## 8. 접근성 메모

- 결과 칩 묶음은 보이는 "결과" 글자로 이름 붙은 `role=group`, 채널은 `ToggleGroup`(`aria-label` 채널, 보이는 글자는 `aria-hidden`).
- 결과 열·칩은 아이콘(`aria-hidden`) + 글자. 빈 값은 "—" + sr-only "없음".
- 카드 그림은 `role=img` + 이름, 숫자는 범례 글자로도 읽힘.
- 세션 바뀜(`session_changed`): 토스트(sonner live region)로 이유를 말하고 대시보드로 이동.
