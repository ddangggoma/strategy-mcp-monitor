# 화면 설계 — MCP 화면군 (대시보드·목록·상세·스크립트·등록)

Task 10 산출물(Task 11·12가 이어서 채웁니다). `frontend-design` 스킬로 `docs/design/direction.md`(고성능 HMI 관제 콘솔)를 관리 화면의 MCP 일에 적용했습니다. 문구는 `design:ux-copy`(해요체, `web/src/copy/ko.ts`), 움직임은 audit-suite `web-animation-design`, React 구조는 `vercel-react-best-practices`, 자체 점검은 `audit-as-ux-eng`·`audit-as-a11y-eng`. 토큰·컴포넌트 규칙은 `docs/design/design-system.md`.

## 1. 일

- **대시보드:** 로그인한 사람이 처음 보는 곳. "지금 무엇이 망가졌나(상태별 개수) → 누가 접속해 있나 → 최근에 무슨 일이 있었나"를 한 화면에서 답하고, 개수 하나를 누르면 그 상태만 거른 목록으로 갑니다.
- **목록:** 모든 MCP를 한 표에. 문제가 위(U17), 행마다 바로 시작·다시 시작·종료. 표는 실시간으로 바뀌지만 다시 불러오지 않습니다(SSE → `connectLive` → 쿼리 캐시).
- **상세(Task 11·12):** 한 MCP의 설정·스크립트·이력. 머리에 같은 `McpActions`.

## 2. 이 화면군의 한 가지 대담함

관리 화면은 조용합니다. 이 화면군에서 눈에 띄는 것은 **상태 배지 하나뿐**이고, 그것도 보드와 같은 규칙(정상은 작은 초록 아이콘, 문제는 soft 채움 + 아이콘 + 글자)을 따릅니다. 버튼은 hue가 없는 명도 강조(secondary 채움, 종료만 outline), 링크는 굵기와 밑줄. 그래서 표를 훑으면 색이 있는 칸이 곧 문제 있는 MCP입니다.

## 3. 대시보드 (`/admin`)

```
대시보드                                                         ← h1 text-xl
┌ MCP 요약 ──────────────────────────────┐┌ 현재 세션 ─────────────────┐   ← xl 이상 2열
│ [전체 4][⊗실패 1][🔧조치 중 0]…[✓정상 3] ││ ● 접속 중 / 수집 전 안내     │
│  개수 > 0 → 링크(/admin/mcps?state=)    ││ 접속자 카드(SessionCard)     │
│  0 → 점선 테두리 글자(링크 아님)         │└─────────────────────────────┘
└─────────────────────────────────────────┘
┌ 최근 이슈와 조치 (전체 폭) ─────────────────────────────────────────┐
│ 시각(KST)            MCP             내용                             │
│ 2026-11-06 02:25:06  calculator      수동 종료 ✓성공                  │
│ 2026-11-06 02:24:43  seoul-weather   [⚠이상 감지] 프로세스 중지        │
└──────────────────────────────────────────────────────────────────────┘
┌ 로그인 실패 추이 ──────┐┌ 우회 탐지 이벤트 ──────┐  ← PlannedFeature planned_logs(U13, 가짜 데이터 없음)
```

- 카드는 `section[aria-labelledby]` + h2. 1열(1280px 미만) → 2열(`xl`). 활동 카드는 항상 전체 폭.
- **MCP 요약:** 데이터는 BoardStore(보드와 같은 실시간 값). 타일 격자는 카드 폭 컨테이너 쿼리로 2 → 4(`@sm`) → 7(`@2xl`)열. 첫 보드 이벤트 전에는 타일 모양 스켈레톤 + `role=status` "불러오는 중…". MCP가 없으면 "등록된 MCP가 없어요."
- **현재 세션:** 보드의 `ConnectionBanner` + `SessionCard` 그대로(Plan 4 전에는 수집 전 안내).
- **최근 이슈와 조치:** `GET /api/mcp-activity?limit=50`에서 HEALTHY가 아닌 상태로의 전이와 모든 조치 단계를 시각 역순으로 10개. 시각은 KST `YYYY-MM-DD HH:mm:ss`(U28), MCP 이름은 상세 링크. 전이는 `StatusBadge`(상태 + 이슈), 조치는 "자동 다시 시작" + 결과(아이콘 + 성공/실패/시간 초과/실행 오류, 실패류는 `fg` 굵게, 성공은 muted). 시각·MCP 열은 내용 폭(`w-px`), 내용 열이 나머지. 비어 있으면 "최근 이슈나 조치가 없어요.", 실패하면 `role=alert` 문장.

## 4. 목록 (`/admin/mcps?state=`)

```
MCP                                                            [+ MCP 등록]
[전체 4][⊗실패 0][🔧조치 중 1][⚠이상 감지 1][⟳복구 중 0][⏸점검 중 1][✓정상 1]   ← nav "상태로 거르기"
┌ 상태 ↑ ─ 이름 ⇅ ─ 호스트:포트 ─ 지연(ms) ⇅ ─ 24시간 가동률 ⇅ ─ 소유자 ─┬ 조치 ┐
│ [🔧조치 중]  calculator  127.0.0.1:8700        4        100.0%   관리자 │ ▶ ⟳ ■ │  ← 36px 행
│ [⚠이상 감지] 프로세스 중지  seoul-weather …                              │       │
└────────────────────────────────────────────────────────────────────────┴───────┘
                                                        조치 열은 sticky right-0 ↑
```

- **표:** TanStack Table v9(`useTable` + `rowSortingFeature`). 이름 칸은 `th scope=row`(행의 이름이 조치 버튼의 맥락), 머리는 `th scope=col` + 정렬 가능한 열에 `aria-sort`와 버튼(↑/↓/⇅ 아이콘). 기본 정렬 = 설정 오류 → U17 심각도 → 이름, 같은 값은 이름으로. 지연·가동률은 값이 없으면 방향과 상관없이 맨 뒤. 숫자 열은 오른쪽 정렬 `tabular-nums`, 호스트:포트는 모노(복사·대조하는 기계 값).
- **행에 애니메이션 없음**(direction §6). 대신 포인터가 표 본문 위에 있는 동안은 실시간 상태 변화가 와도 **행 순서를 고정**하고, 포인터가 나가면 다시 정렬합니다. 시작을 누른 행이 "조치 중"이 되어 맨 위로 뛰면, 다음 클릭이 다른 MCP의 버튼에 떨어질 수 있기 때문입니다(자체 점검에서 발견).
- **필터 칩:** `nav[aria-label=상태로 거르기]` 안 링크. 현재 칩은 TanStack 활성 판정(`exact`)으로 `aria-current=page` + `selected` 채움 + `fg` 테두리. 개수 0인 칩은 muted지만 누를 수 있습니다(칩 줄이 흔들리지 않게 6개 상태를 늘 보임). 거른 결과가 없으면 "지금 점검 중 상태인 MCP가 없어요." + "모든 MCP 보기" 링크.
- **상태 칸:** `StatusBadge`(상태 + 이슈). 설정 오류는 테두리만 있는 중립 배지(⚠ 팔각형 아이콘 + "설정 오류") — 감시하지 않는 MCP라 상태 hue를 쓰지 않습니다. 보드가 아직 보고하지 않은 MCP는 "상태 기록 없음".
- **"MCP 등록":** 허용되면 주 버튼 모양의 링크(`/admin/mcps/new`), 아니면 같은 모양의 `aria-disabled` 버튼 + 이유(원격 모드 → `deny.local_only`, 툴팁은 왼쪽).
- **좁은 창:** 페이지는 옆으로 스크롤하지 않고 표만 자기 틀 안에서 스크롤합니다. 조치 열은 `sticky right-0`(왼쪽 헤어라인)이라 1024px에서도 버튼이 보입니다. 640px에서 칩은 두 줄로 접힙니다.
- **빈 목록:** "등록된 MCP가 없어요. MCP를 등록하면 여기서 상태를 보고 직접 시작하거나 종료할 수 있어요." + 위의 등록 버튼. 로딩은 행 높이 스켈레톤 4줄 + `role=status`.

## 5. 수동 조치 (`McpActions`)와 토스트 흐름

| 크기 | 모습 |
|---|---|
| `md`(상세 머리, Task 11) | 아이콘 + 글자 버튼 36px: 시작·다시 시작(secondary), 종료(outline) |
| `sm`(목록 행) | 28px 아이콘 버튼, 이름은 `aria-label` + 툴팁. 비활성이면 툴팁에 이름 + 이유 |

- **비활성 이유(순서):** 권한(`mcp_manual_action`) → 스크립트 실행 중(`live.running` → `deny.running`) → 설정 오류(`deny.config_error`). `aria-disabled` + 클릭·Enter 무시 + 설명(U26).
- **종료 확인:** AlertDialog "calc을(를) 종료할까요?" / `mcp.stopConfirm`(점검 모드로 바뀌어 자동 복구가 멈춤, 다시 시작하면 풀림) / [취소] [종료(destructive)]. 닫히면 포커스는 종료 버튼으로 돌아갑니다(상태로 연 대화상자라 Radix 트리거가 없음).
- **요청 중:** 누른 버튼에 `aria-busy`, 두 번 눌러도 요청은 하나. 409 `action_in_progress`와 그 밖의 오류는 오류 토스트(`copy.errors.*`).
- **토스트(U29, 이 탭이 보낸 `run_id`만):** 하나의 토스트가 `id = run_id`로 제자리에서 바뀝니다.

```
202 {run_id} ─▶ ⟳ "calc 다시 시작 중…"                      (loading, 닫히지 않음)
   SSE action(requested=restart, kind=stop) ─▶ 같은 토스트 + "종료 단계를 마쳤어요. 이어서 시작하는 중이에요."
   SSE action(최종 단계) ─▶ ok:     ✓ "calc 다시 시작 완료" / "종료 코드 0, 1.2초 걸렸어요."      (4초)
                           failed: ⊗ "calc 다시 시작 실패" / "종료 코드 3, 0.3초 걸렸어요." [이력 보기] (15초)
                           timeout:⊗ … 실패 / "제한 시간을 넘겨 중단했어요. 2분 걸렸어요." [이력 보기]
                           error:  ⊗ … 실패 / "스크립트를 실행하지 못했어요. 이력에서 원인을 확인하세요." [이력 보기]
   스트림 재연결 ─▶ GET /api/mcps/{id}/history?hours=1 에서 같은 run_id의 최종 단계를 찾아 위와 같이 끝냄
   마감(2×script_timeout_sec+30초, F24)까지 결과 없음 ─▶ 이력 한 번 더 확인 → 없으면
                           ⚠ "calc 조치 결과를 확인하지 못했어요. 이력에서 확인하세요." [이력 보기]
                           (그 뒤 1시간 안에 늦은 이벤트가 오면 같은 토스트가 결과로 바뀜)
```

- [이력 보기] = `/admin/mcps/$id?tab=history`(TanStack Link, 토스트 안에서도 SPA 이동).
- 202보다 결과 이벤트가 먼저 와도(아주 짧은 스크립트) 30초 동안 기억했다가 추적을 시작할 때 이어 붙입니다.
- 로그아웃·세션 만료로 셸이 사라지면 토스트를 모두 닫습니다. Sonner는 토스트를 전역에 두고 다음 Toaster에 다시 보여 주므로, 추적하지 않는 "… 중" 토스트가 영원히 돌 수 있기 때문입니다.
- 접근성: Sonner의 `aria-live` 영역이 시작·결과를 읽습니다. 결과는 아이콘(상태 색) + 글자.

## 6. 상세·스크립트·등록·대화상자 (Task 11·12에서 확정)

이 절은 Task 10에서 틀만 정하고, 각 과제가 자기 화면을 채운 뒤 갱신합니다.

- **상세 머리(Task 11 확정):** h1 이름 + `StatusBadge`(lg) 또는 설정 오류 배지 + 호스트:포트(모노)·소유자(`dl`) / 오른쪽에 `McpActions size="md"` · 헤어라인 · ghost 버튼 "소유권 이전"·"삭제"(권한 없으면 `aria-disabled` + 이유: 이전 `admin_only`/`local_only`, 삭제 `owner_only`/`no_owner`/`local_only`). 좁은 창에서는 버튼 줄이 이름 아래로 접힙니다. 설정 오류면 머리 아래 `role=alert` 띠(`mcp.configError`, 상태 hue 없음, 테두리 strong), 설정 탭은 열자마자 규칙에 어긋난 칸을 표시합니다.
- **탭 3개**(`?tab=settings|scripts|history`, Tabs `line`, `replace` 이동). 설정 탭은 다른 탭을 보는 동안에도 마운트된 채 숨겨져 고치던 값이 남습니다. 저장하지 않은 값이 있으면 다른 페이지로 갈 때 "저장하지 않은 변경 사항이 있어요" 확인(`LeaveGuard`, 새로 고침·탭 닫기는 브라우저 확인). 삭제 뒤 이동과 세션 만료는 묻지 않습니다.
- **설정 폼:** `--size-prose` 폭, `fieldset` 세 묶음(연결과 점검 / 자동 복구 / 운영), 넓으면 2열(컨테이너 쿼리 `@lg`). 숫자 칸 아래 "허용 범위 a–b", 이름 칸 아래 `mcp.nameRule`(오류일 때는 오류 문장만). 실시간 갱신은 고치지 않은 칸만 바꿉니다(`keepDirtyValues`, 안내 `mcp.liveNote`). 저장 = 바뀐 칸만 PUT(U27), 바뀐 것이 없으면 저장·변경 취소가 `aria-disabled`. 409 `name_taken`→이름 칸, `endpoint_taken`→포트 칸(포커스 이동), 422·그 밖→폼 아래 `role=alert`. 성공은 "저장했어요" 토스트. 저장 중에는 입력이 읽기 전용.
- **이력 탭:** 기간 토글(1시간·6시간·24시간·7일, `aria-pressed`, URL에 넣지 않음) → "지연과 가동률"(평균·최대·가동률 수치 + 차트) → "상태 전이" 표 → "조치 기록" 표. 기간을 바꾸는 동안 이전 기간을 60% 불투명도로 유지(깜박임 없음). 조치 행 클릭(또는 시각 버튼 Enter) → 실행 결과 대화상자(사실 `dl` + 표준 출력·표준 오류 `<pre>`, 잘림 안내 `mcp.truncated`, 닫으면 그 행 버튼으로 포커스 복귀).
- **차트(`dataviz`):** y축 하나 규칙 때문에 지연(ms)과 가동률(%)을 **두 개의 플롯**으로 쌓고 시간축·십자선(syncId)을 공유합니다(이중 축 금지). hue는 상태 전용이라 지연 선은 중립: 평균 = `fg` 2px, 최대 = `fg-muted` 1.5px. 가동률 = `fg` 10% 면 + `fg-muted` 계단선. 전이 시점만 상태 색 1px 세로선(바뀐 뒤 상태의 색). 격자·축은 `border` 헤어라인, 눈금 글자는 `fg-muted` 12px. 눈금 간격은 **보이는 데이터의 길이**로 고릅니다(새 MCP는 7일 보기에서도 몇 분뿐). 범례는 HTML(선 키·면 키·세로선 키), 툴팁은 값 먼저·이름 뒤(시각 KST). 최대 720점으로 줄임(`downsample`). 애니메이션 없음. Recharts는 이력 탭을 열 때 받는 별도 청크(110KB gz). 표가 차트의 표 쌍둥이 역할을 하고, 그림 캡션에 기간 요약 문장(스크린 리더).
- **스크립트:** 읽기 전용은 `<pre>`(sunken, 모노), 편집은 로컬 소유자만 CodeMirror 지연 로드. 버전 목록 + diff(jsdiff `diffLines`, U19), 초안 복원 안내(`scripts.draftRestored`).
- **등록 폼**(`/admin/mcps/new`, Local): 이름 규칙(`mcp.nameRule`) 아래 도움말, 시작·종료 스크립트 필수.
- **소유권 이전·삭제:** AlertDialog. 삭제는 이름을 그대로 입력해야 "MCP 삭제"가 켜짐(`mcp.deleteConfirm`).
- **권한별 비활성 모습:** 외부 채널(등록·삭제·스크립트 편집·소유권 → `local_only`), 비소유 개발자(스크립트 편집 → `owner_only`), 소유자 없음(→ `no_owner`). 모두 보이되 `aria-disabled` + 이유.

- **소유권 이전**(Dialog): 활성 사용자만 Select로(지금 소유자는 보이되 고를 수 없음, 이름 + 이메일), 사용자 목록은 대화상자를 열 때만 요청. 성공 → 토스트 "X의 소유자를 Y(으)로 바꿨어요." + 머리 갱신, 422 `invalid_owner` → 대화상자 안 `role=alert`.
- **삭제**(AlertDialog): 이름을 그대로 입력해야 "MCP 삭제"(destructive)가 켜짐, 안내는 `mcp.deleteConfirm`(종료 스크립트 미실행). 204 → 목록 + 토스트, 409 → 대화상자 안 오류.

## 8. 접근성

- 랜드마크: 셸의 `nav`·`main` 안에 h1 → 카드 h2. 대시보드 카드는 이름 있는 `region`.
- 목록 표: `aria-label="MCP 목록"`, 행 머리 = 이름, `aria-sort`, 정렬 버튼은 머리 글자가 이름. 조치 묶음은 `role=group aria-label="calc 조치"`.
- 아이콘 버튼은 `aria-label`(동작 이름), 툴팁 글자는 `aria-hidden`(이름이 두 번 읽히지 않게).
- 실시간 표 변화는 읽지 않습니다(5초마다 읽으면 소음). 결과는 토스트, 보드의 판정 문장이 `aria-live`.
- 포커스: 표가 다시 정렬돼도 행이 `getRowId`로 유지돼 포커스를 잃지 않습니다. 종료 대화상자 → 종료 버튼으로 복귀.
