# 화면 설계 — 로그 조회(`/admin/logs`)

Plan 5 Task 11 산출물. `frontend-design` 스킬로 `docs/design/direction.md`(고성능 HMI 관제 콘솔)와 `screens/sessions.md`(감사 기록 표의 밀도)를 로그 조회에 적용했고, 히스토그램·타임라인은 `dataviz` 스킬(형태 → 색 → 검증기 → 표식 → 호버 → 접근성)로 정했습니다. 문구는 `design:ux-copy`(해요체, `web/src/copy/ko.ts`의 `logs`), React 구조는 `vercel-react-best-practices`, 움직임은 `web-animation-design`(로그 영역 전체 무애니메이션). 창 폭은 W41대로 1920·1280·1024·800·640(640×600)에서 확인하고 휴대폰 배치는 만들지 않습니다.

## 1. 일

- **누가:** 로그인한 MCP 개발자와 Admin, 두 채널 모두(`view_logs`). 내보내기는 `export_logs`.
- **첫째 일:** "그때 무슨 일이 있었나"를 좁혀 가는 것 — 시간대를 고르고(히스토그램 드래그 또는 빠른 선택), 사람·카테고리·세션·IP·낱말로 거른 뒤, 한 줄을 열어 원문을 봅니다.
- **둘째 일:** "누가 언제 활동했나"를 사람별로 훑기(타임라인) → 칸 하나를 눌러 그 사람·그 시간의 표로 내려가기.
- **이 화면의 상태는 URL 하나입니다(W34).** 필터·구간·보기를 바꾸면 주소가 바뀌고, 그 주소를 동료에게 보내면 같은 화면이 열립니다.

## 2. 한 가지 대담함: 시간 띠

화면에서 눈에 띄는 것은 **히스토그램 하나**입니다. 화면 폭 전체를 가로지르는 시간 띠 위에 다섯 묶음 색의 누적 막대가 서 있고, 그 위를 끌면 구간이 반전 채움(`selected`)으로 덮이며 손을 떼는 순간 표가 그 구간으로 좁혀집니다. 나머지(필터 칩·입력칸·표)는 중립 잉크와 헤어라인뿐입니다. 색은 히스토그램 막대, 카테고리 칩의 점, 표 카테고리 열의 점에만 쓰고, 글자는 언제나 글자 색입니다(dataviz: 글자는 계열 색을 입지 않음).

템플릿 기본값을 피한 근거:

| 흔한 기본값 | 이 화면의 선택 |
|---|---|
| 차트 라이브러리 기본 막대(둥근 모서리, 그리드, 범례 상자) | 직접 그린 SVG(W32). 시간 칸은 연속이라 칸을 꽉 채운 사각 막대(`max(2, 폭/n − 1)`px, 1px 틈), 그리드 없음, 최댓값 한 줄만 |
| 12색 카테고리 | 다섯 묶음 색(W32), 검증기를 통과한 순서로 쌓음(§4) |
| 필터를 옆 패널(사이드바)에 | 위쪽 한 덩어리 필터 막대(dataviz "필터는 차트 위 한 줄"), 컨테이너 쿼리로 접힘 |
| 무한 스크롤 표 + 페이지 전체 스크롤 | 표가 자기 틀에서만 스크롤(높이 = 남은 뷰포트), 끝 20행 전에 다음 페이지 |

- **필터 막대**는 `@container`(이름 `filters`)입니다. 넓으면 세 줄(기간 / 카테고리 / 사람·조건·내보내기), 좁으면 각 줄 안의 묶음이 `flex-wrap`으로 접혀 640 창에서 5–6줄이 됩니다. 어떤 폭에서도 가로로 넘치지 않습니다(입력칸 최소 폭 `min(100%, 11rem)`).
- **히스토그램 막대 수**는 컨테이너 너비로 정합니다: ≥ 1024px → 60, ≥ 640px → 40, 그 밖 → 24(모두 서버 최소 10 이상). 640 창(사이드 레일 제외 본문 ≈ 530px)에서는 24개 → 막대 ≈ 21px.
- **보기 전환**은 `aria-pressed` 묶음(세션 화면의 기간 버튼과 같은 모양). 표가 기본이라 URL에 쓰지 않고, 타임라인만 `?view=timeline`.
- **표**는 `table-layout: fixed` + 열 폭 고정(가상 스크롤에서 행이 바뀌어도 열이 흔들리지 않음). 열 합계 ≈ 76rem이라 1280 이하에서는 틀 안에서 가로 스크롤합니다. 틀 높이 = 창 높이 − 틀 위치 − 24px, 단 창 높이의 절반·240px보다 작지 않음. 그래서 1920×1080에서는 페이지가 스크롤되지 않고 표만 스크롤됩니다. 필터가 여러 줄로 접히는 창(1280×800 이하)에서는 표가 창의 절반 높이를 받고 페이지가 세로로만 조금 스크롤됩니다(가로는 언제나 표 틀 안에서만).
- **타임라인**은 `@container`(이름 `timeline`). ≥ 36rem: `[이름·합계 12rem][칸 띠 1fr]` 두 열. 그보다 좁으면 이름·합계가 칸 띠 위로 올라갑니다. 칸 진하기 = `color-mix(in oklch, var(--color-accent) <비율>%, transparent)`(비율 = 칸 건수 / 사람 줄 전체의 최대 칸 건수, 0이 아니면 최소 12%). "그 밖의 사용자"(여러 사람의 합)와 "사용자 없음"은 사람이 아니라서 자기 줄의 최대로 따로 맞추고 `fg-muted` 잉크로 칠합니다 — 합계 줄이 척도를 차지하면 사람 줄이 모두 흐려집니다(실제 백엔드에서 확인한 문제). 칸 높이 20px, 1px 틈, 빈 칸은 `sunken` 띠.
- **상세 대화상자**: 시각·카테고리·사용자·세션·IP·이벤트(`dl`) + 원문 JSON `<pre>`(자기 스크롤) + "이 사용자로 거르기"·"이 세션으로 거르기" + 닫기. 패널은 `max-inline-size: calc(100vw − 32px)`, 높이 `calc(100dvh − 32px)`를 넘지 않고 **패널 자체는 스크롤하지 않습니다**(원문만 스크롤) — 그래서 오른쪽 위 닫기(X)와 아래 "닫기" 버튼이 언제나 보입니다.

## 4. 색 — 카테고리 묶음 5색

12개 카테고리를 다섯 묶음(`categories.ts` `CATEGORY_GROUP`)으로 칠합니다(W32). 상태 6색(green 152·amber 85·orange 52·cyan 212·red 22·slate 255)과 겹치지 않는 hue만 씁니다.

| 묶음 | 카테고리 | hue | 라이트(600) | 다크(400) |
|---|---|---|---|---|
| 보안 | 우회 탐지, 웹 로그인, 관리 작업 | magenta 355 | `oklch(0.45 0.16 355)` #931e5a | `oklch(0.6 0.16 355)` #c65085 |
| 접속 | 원격 접속, 사전 고지 | blue 250 | `oklch(0.56 0.155 250)` #0a77cb | `oklch(0.6 0.16 250)` #1a83db |
| 시스템 | 시스템 이벤트 | olive 115 | `oklch(0.6 0.135 115)` #7e8904 | 같음 |
| 활동 | 프로세스, 명령, 창 전환, 유휴 | violet 300 | `oklch(0.45 0.16 300)` #65389f | `oklch(0.6 0.16 300)` #9065d0 |
| MCP | MCP 상태, MCP 조치 | teal 185 | `oklch(0.6 0.105 185)` #059488 | `oklch(0.66 0.115 185)` #0aa99b |

- **쌓는 순서(아래 → 위) = 표의 순서 = 범례 순서**: 보안 → 접속 → 시스템 → 활동 → MCP(`GROUP_STACK`). 보안이 기준선에 붙어 있어 높이를 가장 잘 비교할 수 있습니다(우회 탐지·로그인 실패가 다시 볼 일).
- **검증(dataviz `validate_palette.js`, 인접 쌍):** 라이트 — 밝기 띠·채도 하한·대비 3:1 통과, CVD ΔE 최소 18.0(deutan), 일반 시각 ΔE 최소 27.1. 다크 — 모두 통과, CVD 14.0, 일반 24.3. Task 10의 첫 팔레트(blue 0.55/violet 0.55, 시스템 = 강철 회색)는 파랑↔보라가 deutan ΔE 0.7로 사실상 같은 색이고 회색이 채도 하한에 걸려 실패했습니다 → 밝기를 쌓는 순서에 따라 번갈아 두고 시스템을 olive로 바꿨습니다. 이 규칙은 `tokens.contrast.test.ts`의 "stacked category neighbours stay apart …"(Machado 2009 시뮬레이션)로 고정합니다.
- 모든 쌍(인접이 아닌 쌍) 검사는 다크 파랑↔보라가 CVD 2.6으로 통과하지 못합니다. 이 둘은 쌓을 때 맞닿지 않고, 칩·표에서는 점 옆에 언제나 이름 글자가 있어 색만으로 구분하지 않습니다(범례 + 글자 = 보조 부호화).
- 묶음 없는 히스토그램(`group=none`, 감사 화면의 compact 등)은 단색 `fg-muted`.
- 선택 구간은 `selected` 채움 + `border-strong` 테두리, 포커스 칸은 2px `focus` 테두리 — 모두 hue 없음.

## 5. 밀도와 글자

- 관리 표와 같은 `text-sm`, 행 높이 **32px**(가상 스크롤 고정 높이; 세션 화면 36px보다 촘촘 — 로그는 수천 줄을 훑음), 머리 `text-xs` muted, sticky.
- 시각 `YYYY-MM-DD HH:mm:ss.SSS` KST `tabular-nums`, IP·세션 번호·이벤트 이름은 모노(대조하는 기계 값), 사용자 `DOMAIN\user` 그대로. 내용(`summarize`)은 한 줄 말줄임, 전체는 상세에서.
- 히스토그램 축 글자 `text-xs` muted `tabular-nums`, 같은 날이면 `HH:mm`, 여러 날이면 `MM-DD HH:mm`.

## 6. 상태

| 상황 | 표시 |
|---|---|
| 첫 로딩 | 히스토그램 자리 같은 높이 스켈레톤(레이아웃 이동 없음), 표 자리 행 높이 스켈레톤 5줄 + `role=status` "불러오는 중…" |
| 필터를 바꾸는 동안 | 이전 결과를 60% 불투명도로 유지(`aria-busy`), 깜박임 없음 |
| 빈 결과 | `logs.empty` "이 조건에 맞는 로그가 없어요. 기간을 넓히거나 조건을 줄여 보세요." + 바로 옆 [조건 지우기] |
| 색인 중 | 필터 막대 위 배너 `logs.indexing(n)`(정보 아이콘, hue 없음, `role=status`) — 결과는 그대로 보여 주되 빠진 기록이 있을 수 있다고 말함. 5초마다 상태를 다시 읽고 준비되면 사라짐 |
| 오류 | `role=alert` 한 줄 "로그를 불러오지 못했어요. …" |
| 다음 페이지 | 표 맨 아래 상태 줄 "불러오는 중…"(행 아님, 애니메이션 없음) |
| 내보내기 권한 없음 | 버튼은 보이되 `aria-disabled` + 이유 툴팁(`WithReason`) |
| 시작 ≥ 끝 | 적용하지 않고 입력칸 아래 `role=alert` "끝 시각이 시작 시각보다 늦어야 해요." |

## 7. 움직임

**로그 영역에는 움직임이 없습니다**(spec §6.5, W32). 표 행, 다음 페이지로 붙는 행, 히스토그램 막대·선택 사각형·툴팁, 타임라인 칸 모두 `transition`/`animation` 없음, `data-anim` 없음. 필터만 바꾸는 이동은 라우터의 View Transition 크로스페이드를 끕니다(`viewTransition: false`, F16) — 하루 수백 번 하는 조작(웹 애니메이션 스킬: 100+회/일 → 애니메이션 없음). 키워드·세션·IP 입력의 디바운스 이동은 `replace: true`(낱자마다 방문 기록을 쌓지 않음), 히스토그램 선택은 `push`(뒤로 가기로 확대 이전으로 돌아감). 남는 움직임은 공용 컴포넌트의 것뿐입니다: 팝오버·메뉴·대화상자 진입(120–200ms, reduced-motion이면 꺼짐).

## 8. 키보드 경로

- **히스토그램:** Tab으로 SVG(`role=group`, 이름 = 범위·합계·사용법)에 들어가면 포커스 칸 0. ←/→ 칸 이동, Shift+←/→ 선택 확장(기준 칸 고정), Enter 적용(선택 없으면 포커스 칸 하나), Escape 선택 해제 + 포커스를 기준 칸으로(F19). 포커스·선택은 `aria-live=polite` 영역에 `logs.selection(시작, 끝, 건수)`.
- **사용자 필터:** 버튼 → 팝오버(cmdk): 입력칸에서 이름 거르기, ↑/↓, Enter로 체크 토글(팝오버는 열린 채), Escape로 닫고 버튼으로 돌아감.
- **표:** 로빙 tabindex — 표 안에서 Tab 순서에 있는 행은 하나(마지막으로 포커스한 행, 그 행이 렌더 창 밖이면 보이는 첫 행)라서 Tab 한 번으로 표를 지나갑니다. ↑/↓ 행 이동(가상 스크롤이 따라감), Enter·클릭으로 상세. 대화상자를 닫으면 그 행으로 돌아가고, 상세에서 거른 탓에 행이 사라졌으면 표의 첫 행(없으면 본문)으로.
- **타임라인:** 줄마다 `role=group`(이름 = 사용자·합계·사용법), 로빙 tabindex로 한 줄만 Tab 순서, ↑/↓ 줄 이동, ←/→ 칸 이동, Enter → 그 사용자·그 칸의 표. "그 밖의 사용자"·"사용자 없음" 줄은 누를 수 없고 Tab에서 빠짐.

## 9. 접근성 메모

- 표 이름 `aria-label="로그"`, `aria-rowcount`(더 있으면 −1), 행 `aria-rowindex`, 가상 여백 `<tr aria-hidden>`.
- 카테고리 칩 `aria-pressed`, 묶음 `role=group aria-label=<묶음 이름>`, 색 점 `aria-hidden`.
- 툴팁(호버)은 눈으로만(`aria-hidden`), 같은 정보를 라이브 영역과 표가 전합니다(dataviz: 표 보기 = 표 자체).
- 도움말 팝오버: 명령 로그가 기록하지 않는 것(spec §2 #7).
