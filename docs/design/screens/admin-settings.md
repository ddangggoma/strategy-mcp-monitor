# 화면 설계 — 관리 설정 화면군 (사용자·설정·고지 편집기·원격 모드 빈 상태)

Task 13 산출물(Task 14가 고지 편집기 절을 확정합니다). `frontend-design` 스킬로 `docs/design/direction.md`(고성능 HMI 관제 콘솔)를 Admin의 관리 일에 적용했습니다. 문구는 `design:ux-copy`(해요체, `web/src/copy/ko.ts`), React 구조는 audit-suite `vercel-react-best-practices`, 자체 점검은 `audit-as-ux-eng`·`audit-as-a11y-eng`. 토큰·컴포넌트 규칙은 `docs/design/design-system.md`.

## 1. 일

- **사용자(`/admin/users`, Local·Admin):** 누가 이 콘솔을 쓸 수 있는지 정합니다. 추가, 역할(MCP 개발자 ↔ Admin), 활성/비활성, 이름 고치기. 하루에 몇 번 보지 않는 화면이지만, 한 번의 실수(마지막 Admin을 잃음, 동료를 의도치 않게 로그아웃시킴)가 비쌉니다.
- **설정(`/admin/settings`, Local·Admin):** 감시 주기, 로그 보존, 부팅 시작 유형. 대부분은 숫자 몇 개지만 **보존 기간을 줄이는 저장은 로그를 지웁니다.**
- **사전 고지(`/admin/notice`, Local·Admin, Task 14):** 원격 접속 때 보이는 안내문 편집.
- **원격 모드:** 이 세 화면은 Local 전용입니다. 다른 PC에서 주소로 바로 들어오면 이유 한 문장만 보여 주고 아무것도 요청하지 않습니다.

## 2. 이 화면군의 한 가지 대담함

관리 화면은 조용합니다(hue는 상태 전용). 이 화면군에서 크게 말하는 것은 **보존 기간을 줄일 때의 확인 대화상자 하나**입니다. 그 안의 "삭제될 기간"(날짜 두 개)과 파일 수·용량을 `text-lg` `tabular-nums`로, 설명 문장보다 크게 둡니다. 되돌릴 수 없는 결과를 숫자로 먼저 보게 하는 것이 이 화면군의 얼굴입니다. 그 밖에는 경고색도 아이콘 장식도 없습니다.

템플릿 기본값과 다르게 고른 것:

| 흔한 기본값 | 이 화면군의 선택 |
|---|---|
| 설정 화면 = 카드 여러 장 | 카드 없음. MCP 설정 탭과 같은 `fieldset` + 위 헤어라인(legend)으로 묶은 한 폼, 저장 버튼 하나. |
| "정말 하시겠습니까?" 확인 | 결과를 말하는 제목("오래된 로그를 삭제할까요?", "user2을(를) 비활성화할까요?")과 결과를 이름으로 단 버튼("줄이고 삭제", "비활성화"). |
| 행마다 "⋯" 메뉴에 숨긴 동작 | 역할·활성은 행 안에서 바로 보이는 컨트롤. 이름 편집만 연필 아이콘 버튼(이름 있는 버튼). |
| 비활성 컨트롤을 회색으로만 | 마지막 Admin의 두 컨트롤은 `aria-disabled` + **행 안에 보이는 이유 문장**(툴팁에만 숨기지 않음). |

## 3. 사용자 (`UsersPage`)

```
사용자                                                              [+ 사용자 추가]
┌ 이름 ──────────────── 이메일 ─────────────── 역할 ───────── 활성 ── 마지막 로그인 ────── 소유 MCP ┐
│ 관리자               admin@corp.kr          [Admin      ▾]  (●)   2026-11-04 14:03:22        0  [✎ 이름 편집] │
│                                             🛡 마지막 Admin이라 역할을…  ← 역할 칸 아래 muted, 두 컨트롤의 설명       │
│ 홍길동               hong@corp.kr           [MCP 개발자 ▾]  (●)   로그인 기록 없음            2  [✎ 이름 편집] │
│ 김민지  비활성        kim@corp.kr            [MCP 개발자 ▾]  ( )   로그인 기록 없음            0  [✎ 이름 편집] │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **표:** shadcn `Table`(애니메이션 없음, 행 hover 색 전환 없음). 이름 칸은 `th scope=row`이고 **이름(과 비활성 배지)만** 담습니다 — 행 머리는 칸마다 먼저 읽히므로, 안내 문장·편집 버튼을 넣으면 칸마다 같이 읽힙니다(a11y 자체 점검에서 고침). 순서는 서버 순서(가입 순) — 정렬 기능 없음(사용자 수가 적고, 바뀌면 행이 뛰어 다음 클릭이 다른 사람에게 떨어집니다). 소유 MCP는 오른쪽 정렬 `tabular-nums`, 마지막 로그인은 KST `YYYY-MM-DD HH:mm:ss`(U28), 없으면 muted "로그인 기록 없음". 이메일은 Pretendard(기계 값이지만 사람이 읽는 주소라 모노를 쓰지 않음).
- **비활성 사용자:** 행 글자를 `fg-muted`로, 이름 옆에 중립 배지 "비활성". 색이 아니라 글자로 구분.
- **역할:** 행 안 Select(MCP 개발자 / Admin, 36px). 고르면 바로 바꾸지 않고 확인 대화상자.
- **활성:** 행 안 Switch. 끄면 확인 대화상자, 켜는 것은 확인 없이 바로(로그아웃될 세션이 없음).
- **확인 대화상자(AlertDialog):** 제목 = 결과("user2의 역할을 Admin(으)로 바꿀까요?", "user2을(를) 비활성화할까요?"), 본문 = `users.revokeNotice`(그 사용자는 바로 로그아웃). 자기 자신이면 한 줄 더: "내 계정이라 저장하면 나도 로그아웃돼요. 다시 로그인해야 해요." 버튼 = [취소] [역할 바꾸기 / 비활성화(destructive)]. 닫히면 포커스는 그 컨트롤로 돌아갑니다.
- **마지막 활성 Admin:** 그 사람의 역할 Select와 활성 Switch는 `aria-disabled`(포커스는 됨, 열리거나 바뀌지 않음) + 역할 칸 아래 보이는 한 줄 `users.lastAdmin`(방패 아이콘, muted)이 두 컨트롤의 `aria-describedby`. 서버가 409 `last_admin`을 주면(다른 탭에서 동시에 바꾼 경우) 같은 뜻의 `errors.last_admin` 오류 토스트.
- **이름 편집:** 마지막 열(머리는 화면 낭독용 "동작")의 ghost 버튼 "✎ 이름 편집"(`aria-label` "user2 이름 편집", 보이는 글자를 이름에 포함) → Dialog(이름 칸 1–100자, 앞뒤 공백 제거, 비면 칸 오류) → PATCH `{name}` → "이름을 바꿨어요." 토스트.
- **사용자 추가:** 머리 오른쪽 주 버튼 → Dialog(이메일, 이름, 역할 Select 기본 MCP 개발자). 409 `user_exists`·422 `invalid_email` → 이메일 칸 오류(포커스), 그 밖 → 대화상자 안 `role=alert`. 성공 → "user3을(를) 추가했어요. 이 이메일로 로그인할 수 있어요." 토스트 + 목록 다시 불러옴(소유 MCP 0).
- **요청 중:** 그 행의 컨트롤 `aria-busy`, 두 번째 변경은 무시.
- **자기 자신을 바꿔 세션이 끊김:** 저장 뒤 목록을 다시 불러오면 401 → Task 9 `onUnauthorized` 흐름(로그인 화면, `redirect=/admin/users`, "다시 로그인하세요" 안내).
- **좁은 창:** 페이지는 옆으로 스크롤하지 않고 표만 자기 틀 안에서 스크롤. 640px에서 머리 버튼은 제목 아래로 접힘.
- **로딩·오류·빈 상태:** 행 높이 스켈레톤 4줄 + `role=status`; 실패 `role=alert` 문장; 빈 목록 `users.empty`(실제로는 Admin이 늘 한 명 있음).

```

(폼 폭 --size-prose)

 허용 범위 1–300             허용 범위 5–60

 허용 범위 1–10

 로그 보존 기간(일) [180]   압축 시작(일) [ 30]
 허용 범위 7–3,650          보존 기간 이하(1일 이상)
 ⚠ 압축 시작 일수는 보존 기간보다 길 수 없어요. 두 값을 함께 고치세요.   ← 두 칸에 하나의 오류
 지금 로그  12개 파일, 12.3 MB · 가장 오래된 날짜 2026-04-01           ← dl, retentionPreview(저장된 값)
── 부팅 시작 유형 ───────────────────────────
 [자동(지연된 시작) ▾]
 지금은 값만 저장돼요. 서비스를 설치할 때 이 값이 적용돼요.
── OTP 공급자 ───────────────────────────────
 Dummy(개발용)            (읽기 전용 글자, 입력칸 아님)
── 알림 채널 ────────────────────────────────
 ⧗ 알림 채널은 아직 준비 중이에요.        ← PlannedFeature planned_alerts

```

- **한 폼, 저장 하나.** `fieldset` + legend(위 헤어라인), 컨테이너 `@lg` 이상 2열. 숫자 칸 아래 허용 범위, 오류는 칸 바로 아래. 바뀐 것이 없으면 저장·변경 취소 `aria-disabled`(Enter도 무시). 성공은 "저장했어요" 토스트, 422 등은 폼 아래 `role=alert`.
- **바뀐 칸만 PUT(U27).** 단, 보존 두 값 중 하나라도 바뀌면 둘 다 보냅니다(서버가 둘의 관계를 함께 검사). `otp_provider`는 보내지 않습니다.
- **압축 ≤ 보존:** 클라이언트 스키마가 서버 검사와 같고(`settingsSchema`), 어긋나면 두 칸 모두 `aria-invalid` + 두 칸 아래 **한 번만** 보이는 문장(`settings.retentionBelowCompress`, 두 칸의 설명). 문장은 "둘을 함께 고치라"고 말합니다 — 보존만 줄이면 압축이 걸려서.
- **현재 로그:** `retentionPreview(저장된 보존값)`의 `total_files`·`total_bytes`·`oldest_date`. 로그가 없으면 "아직 저장된 로그 파일이 없어요."
- **보존 기간을 줄여 저장:** 저장을 누르면 먼저 `retentionPreview(새 값)`을 받고(버튼 "확인하는 중…") 확인 대화상자를 엽니다. 늘리거나 그대로면 대화상자 없이 저장.

```
오래된 로그를 삭제할까요?
보존 기간을 180일에서 90일로 줄이면 아래 로그가 삭제 대상이 돼요. 삭제한 로그는 되살릴 수 없어요.
  삭제될 기간   2026-05-09 – 2026-08-05     ← text-lg tabular-nums
  파일          3개
  용량          2.9 MB
                                   [취소] [줄이고 삭제(destructive)]
```

  삭제할 파일이 없으면 기간 자리에 "삭제될 로그 없음", 버튼은 "보존 기간 줄이기"(destructive 아님). 취소하면 아무것도 보내지 않고 폼은 고친 값 그대로. 미리보기 요청이 실패하면 저장하지 않고 폼 아래 오류.
- **부팅 시작 유형:** Select(자동 / 자동(지연된 시작) / 수동) + `settings.startTypeNote`.
- **저장하지 않은 값:** 다른 페이지로 가면 `LeaveGuard`(Task 11) 확인. 세션 만료 이동은 묻지 않음(F12).

## 5. 사전 고지 편집기 (`NoticeEditorPage`, Task 14가 확정)

```
사전 고지                                         [전체 화면 미리보기]
┌ 편집 ────────────────────────┐┌ 실시간 미리보기 ─────────────┐   ← 컨테이너 @4xl 이상 2열, 좁으면 위아래
│ 제목 [....................] 12/80자 ││  (실제 고지 다이얼로그와 같은 렌더러) │
│ 본문 [굵게][목록]                    ││                                     │
│ [textarea ...............] 230/4,000자││                                     │
│ 버튼 문구 [확인] 2/20자              ││              [확인]                 │
│ [저장]                              │└─────────────────────────────────────┘
└─────────────────────────────┘
── 버전 이력 ──  버전 N · 작성자 · KST · "버전 M에서 되돌림" … [이 버전으로 되돌리기]
```

- 미리보기는 `notice/markup.ts` 하나(U14·U15)와 실제 `NoticeDialog`(`mode="preview"`)로 그립니다. 입력마다 바뀌고, `role=group` + `aria-label=고지 미리보기`입니다(`aria-live` 아님 — 타자마다 읽히지 않게). sunken 무대 위에 실제 패널과 같은 클래스를 씁니다. 미리보기 버튼은 그림일 뿐이라 `tabindex=-1` + `aria-disabled`이고, 모양은 실제와 같게 흐리지 않습니다. 넓은 화면(@4xl)에서는 미리보기가 sticky라 긴 본문을 고치는 동안에도 보입니다.
- 칸마다 글자 수 `[...s].length`/한도(코드 포인트, 이모지 1자). 비었거나 한도를 넘으면 그 칸이 `aria-invalid` + 이유 문장(설명으로 연결)이고 저장은 `aria-disabled`. 서버가 제목·버튼 앞뒤 공백을 지우므로 저장 뒤에는 서버가 돌려준 글을 편집기에 다시 씁니다.
- "굵게": 선택을 `**`로 감쌈(줄마다 따로 — 굵게는 줄을 넘지 않음), 선택이 없으면 `****` 사이에 커서. "목록": 선택이 걸친 줄 앞에 `- `, 모두 이미 목록이면 뗌. 누른 뒤 포커스·선택은 본문으로 돌아갑니다.
- 버전 0 = 기본 문구. 서버 이력에는 없으므로 목록 맨 아래에 항상 붙입니다("처음부터 들어 있는 문구"). 같은 내용 저장·되돌리기는 새 버전을 만들지 않음(`notice.unchanged` 토스트). 되돌림 표시는 "버전 M에서 되돌림" / "기본 문구에서 되돌림"(reverted_from 0). 현재 버전의 되돌리기는 `aria-disabled` + 이유. 되돌리기는 AlertDialog(Trigger, 포커스 복귀), 편집 중이면 "편집 중인 내용은 … 그대로 남아요" 한 줄 더.
- 초안 `notice`(sessionStorage, 바뀔 때마다, 서버 글로 돌아가면 지움), 복원 띠 + "초안 버리기", 초안 뒤에 새 버전이 저장됐으면 경고. `LeaveGuard`(경로가 바뀔 때만), 401은 묻지 않고 로그인으로(F12), 초안은 남음(F13).
- "전체 화면 미리보기" = 새 탭이 아니라 이 화면 위에 여는 전체 화면 오버레이(`NoticeFullPreview`, Radix Dialog): 저장된 고지를 `/notice`와 같은 패널·클래스로 같은 backdrop 위에 그립니다. 위 띠에 "미리보기 닫기"와 설명, Esc로도 닫히고, 열면 포커스가 닫기로, 닫으면 버튼으로 돌아갑니다(뒤 편집기는 aria-hidden). 고지 버튼은 기록 없이 미리보기만 닫습니다. 데스크톱 앱은 창이 하나라 새 탭이 앱 창을 `/notice`로 바꿔 돌아갈 길이 없었기 때문입니다. 아래 한 줄은 "저장된 내용을 실제 고지와 똑같이 이 화면 위에 띄워요."
- `/notice`를 직접 연 미리보기 모드에서만 대화상자 위(확인 뒤에는 안내 아래)에 "← 관리 화면으로 돌아가기"(`/admin/notice` 링크)가 있습니다. 표시 모드(에이전트의 실제 고지)에는 절대 없습니다.

### 5.1 `/notice` 단독 화면 (notice 번들, Task 14)

- React·react-dom·notice 파일만 씁니다(초기 JS 79 KB gzip, 예산 테스트가 패키지 목록을 고정). `applyStoredTheme()` → `loadNoticeContent()` → 네이티브 `<dialog>` + `showModal()`.
- 로컬 Admin이면 저장된 고지(`GET /api/notice`), 그 밖의 사람은 기본 문구(F18: 401로 끝나지 않고 Admin 전용 API를 부르지 않음). `/notice`는 로컬 채널에만 있습니다(8701은 404).
- 닫을 수 없음: Escape는 keydown과 `cancel` 둘 다 막고, 그래도 닫히면(Chromium은 막힌 cancel이 반복되면 통과시킴) 다시 엽니다. 버튼만 확인 → `notifyHost({type: "notice_ack", version})`(WebView2 `postMessage`가 있을 때만) → 대화상자를 닫고 "확인했어요. 이 창을 닫아도 돼요."(처음부터 있던 `role=status`). 불러오기 실패 → `role=alert` 한 문장.
- 진입: `@starting-style` scale(0.96) + opacity, 360ms ease-out, `::backdrop`도 같은 시간·이징. reduced-motion이면 전환 없음.
- 본문이 길면 패널 안에서만 스크롤하고(제목·버튼은 보임), 본문은 `tabindex=0`이라 키보드로 스크롤할 수 있습니다.

## 6. 원격 모드·권한 없음 빈 상태 (`LocalOnlyPage`)

- `denyReason(me, action)`이 있으면 제목 + 헤어라인 상자(자물쇠 아이콘 장식 + `copy.deny[reason]` 한 문장)만. 자식(쿼리 포함)은 렌더링하지 않으므로 Local 전용 API를 부르지 않습니다(404 오인 방지, Global Constraints).

## 9. 접근성

- 표 `aria-label`(사용자 목록), 행 머리 = 이름. 역할 Select의 이름은 "역할", 활성 Switch의 이름은 "활성"이고, 둘 다 행의 이름(그리고 마지막 Admin이면 안내 문장)을 `aria-describedby`로 가리켜 Tab으로만 이동해도 누구의 컨트롤인지 들립니다.
- U26: 마지막 Admin의 컨트롤은 `disabled`가 아니라 `aria-disabled`(포커스 가능, 이유가 설명).
- 확인 대화상자는 `alertdialog`, 포커스 가두기·Escape·포커스 복귀(Radix). 오류 토스트는 Sonner live 영역.
- 보존 오류는 두 칸의 `aria-invalid` + 같은 설명 문장. 서버 오류는 `role=alert`.
- 빈 상태 문장은 일반 문단(제목 아래 바로), 아이콘은 `aria-hidden`.
- 상태로 연 확인 대화상자(역할·비활성화·보존)는 Radix 트리거가 없으므로 닫힐 때 포커스를 직접 돌려줍니다: 그 Select·Switch, 또는 저장 버튼.
