# 접근성 리뷰 — Plan 5 화면 (Task 16)

**기준:** WCAG 2.1 AA(+ 2.2 AA 2.5.8 대상 24px) · **날짜:** 2026-11-07 · **스킬:** `design:accessibility-review`

**대상:** 로그 조회(필터 막대, 히스토그램, 표, 상세 대화상자, 사용자별 타임라인), 감사 로그(종류 탭, 결과·채널 필터, 표), 대시보드 "로그인 실패 추이" 카드, 설정 추가분(Windows 서비스 줄, 보존 정리 확인의 기록 건수).

**입력:**
- 실제 백엔드를 띄워 확인했습니다. 임시 루트에 성능 데이터 생성 규칙(`tests/perf/gen.py`)으로 만든 4만 줄을 넣었고, 실행 인자는 `--session-source none --activity off --dev-otp-code`입니다. 브라우저는 Playwright Chromium입니다.
- 로그 화면에서 Tab을 40번 눌러 포커스 순서와 포커스 표시를 확인했습니다.
- 히스토그램은 Shift+화살표 → Enter, 표는 ↑/↓ → Enter → Escape, 타임라인은 ↓/→ → Enter로 조작해 봤습니다.
- `aria-live`와 `role=status|alert` 목록을 확인했습니다.
- 320×300 CSS px(= 640×600 창을 200% 확대)과 1280·1920, 다크 테마를 확인했습니다.
- 코드 검토 대상: `web/src/admin/{logs,audit}/*`, `dashboard/LoginFailuresCard.tsx`, `settings/ServiceSection.tsx`.
- axe(WCAG 2.0/2.1/2.2 A·AA)는 Task 15의 `a11y.spec.ts`가 세 경로 × (기본, 640×600)에서 돌리고, 위반 0건입니다. 이번 최종 검증에서도 다시 돌렸습니다.

**한계:** 실제 스크린 리더(NVDA, 내레이터)로 듣지 않았습니다. "읽히는 것"은 접근성 트리(이름, 역할, live 영역)로 판단했습니다.

## 5. 남은 위험 (Minor)

1. **`datetime-local`의 달력 단추 포커스 표시가 약합니다**(Chromium 기본 1px 상자). 그 단추는 입력 칸의 UA 그림자 DOM 안에 있습니다. `::-webkit-calendar-picker-indicator:focus-visible`도 `input:focus`도 그때는 맞지 않아 CSS로 고칠 수 없었습니다(시도 후 되돌림). 단추를 건너뛰어도 키보드로 날짜·시각을 모두 넣을 수 있습니다.
2. **키워드 도움말은 화면에 보이지 않습니다**(`title` + 스크린 리더용 설명). 보이는 사용자 중 키보드만 쓰는 사람은 읽을 수 없습니다. 필터 막대 높이(640px에서 이미 첫 화면 전체)를 늘리지 않으려고 그대로 두었습니다. 도움말 아이콘 팝오버로 옮기는 것이 다음 후보입니다.
3. **타임라인의 아주 적은 칸(최소 12% 농도)은 배경과 대비가 낮습니다.** 칸의 값은 키보드 live 영역, `title`, 줄 이름의 합계로도 읽을 수 있습니다. 히트맵의 성격상 남겨 둡니다.
4. **실제 스크린 리더 확인은 하지 않았습니다**(NVDA·내레이터). 실기기 점검(`docs/verification/win11-pro-p6-p7.md` P6-1) 때 내레이터로 히스토그램 선택과 상세 대화상자를 한 번 듣는 것을 권합니다.
