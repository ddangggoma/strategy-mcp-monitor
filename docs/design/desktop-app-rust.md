## 2. 결정: 설치 모드 하나 (포터블 제외)

| 기준 | 포터블만 | 설치만 |
|---|---|---|
| 부팅 시 자동 실행 (R5) | ❌ 불가 | ✅ 서비스 `delayed-auto` |
| 로그인 전 감시·MCP 자동 시작 (S1) | ❌ 누군가 로그인해 exe를 켜야 동작 | ✅ |
| RDP 세션·Security 로그·4688 수집 | ❌ / 일부 | ✅ |
| 연결마다 고지 창 (S2) | ❌ 다른 사용자 세션 불가 | ✅ |
| 감사 기록 보존 (S4) | ⚠️ 끄면 감시 공백, 지우면 기록 소실 | ✅ |
| 사용자가 끄면 감시도 꺼짐 | ⚠️ 감사 회피 수단이 됨 | ✅ 일반 사용자는 서비스를 끌 수 없음 |
| 보안 소프트웨어 차단 위험 | ⚠️ 높음 (자기 압축 + 임시 실행) | 낮음 (Program Files, 서명) |
| 깔끔한 제거 | ✅ 자동 | ✅ 앱 및 기능 / `uninstall` |

포터블은 부팅 자동 실행, 로그인 전 감시, RDP 감사·고지를 구조적으로 만족할 수 없습니다. "종료하면 제거"는 **제거 명령 한 번으로 흔적 없이 지워지는 설치**로 대신합니다. 개발·시연용 임시 실행이 필요하면 제품 기능이 아닌 개발자 명령(`--dev`)으로만 둡니다(선택).

### 그 밖의 검토 사항
1. **R2(Rust 단일 exe) ↔ 기존 Python 서버.** 서버(FastAPI, 약 2,100개 테스트)를 Rust로 다시 쓰는 것은 Plan 1–5 전체를 다시 하는 규모입니다. → Rust exe가 **기존 서버 묶음을 안에 품고(embed) 설치하는 설치기·WebView 셸·에이전트**가 되는 구조를 권합니다. 사용자에게는 exe 하나로 보입니다. **(D4)**
2. **보안 소프트웨어.** 서명 없는 exe는 스마트 앱 컨트롤·Defender에 막힐 수 있습니다(Plan 5 W26). → **코드 서명**을 전제로 합니다. **(D5)**
3. **S2(진짜 모달 고지) 해결.** Rust + WebView2라면 고지 창을 최상위 모달 WebView2 창으로 만들 수 있어, Plan 4의 Edge `--app` 대체(V3)를 없앨 수 있습니다. **(D3)**

## 3. 구조

```
mcp-monitor.exe  (Rust, Tauri 2, 서명됨, 약 40–60 MB)
├─ [내장] payload.tar.zst ── 서버 묶음(bin\monitor\mcp-monitor-server.exe, web\, bundle.json)
├─ 모드: app        WebView2 창 + 트레이 아이콘 (관리 화면 = http://127.0.0.1:8700/admin)
├─ 모드: install    UAC 승격 → Program Files 배치·서비스 등록·ACL·감사 정책
├─ 모드: uninstall  서비스 제거·파일 제거·감사 정책 원복 (데이터는 선택)
└─ 모드: agent      (D3=A) RDP 세션마다 실행되는 고지 창·창 이벤트 수집
```

- **WebView:** Tauri 2(내부적으로 WebView2). Win 11에는 WebView2 Evergreen 런타임이 기본 설치되어 있습니다. 화면은 지금의 웹 UI(`web/dist`)를 그대로 씁니다.
- **서버:** 기존 PyInstaller 서버 exe를 그대로 내장·설치합니다. 서비스 호스트·`ShutdownSequence`·채널 분리·RootLock 등 Plan 5까지의 동작이 유지됩니다.
- **실행 방식 판별:** `mcp-monitor.exe`를 실행하면
  1. 서비스가 설치되어 있으면 → **app 모드**: 서비스에 붙어 창만 띄웁니다.
  2. 없으면 → "이 PC에 설치합니다" 안내 → 승격해 **install** → 끝나면 app 모드 창.
  3. 설치본보다 새 버전의 exe를 실행하면 → 업그레이드 안내 → install(업그레이드).
- **단일 인스턴스:** 두 번째 실행은 기존 창을 앞으로 가져옵니다(Tauri single-instance).

## 4. 동작

### 4.1 설치 (R4·R5)
- 첫 실행(또는 `mcp-monitor.exe install`) → UAC 승격 후 다시 실행. 지금 `install.ps1`이 하는 일을 **Rust로 옮깁니다**(PowerShell 실행 정책·인코딩 문제 제거, exe 하나로 완결):
  - `%ProgramFiles%\MCP Monitor\`에 자기 자신과 서버 묶음 배치, 파일마다 SHA-256 검증
  - 서비스 `mcp-monitor` 등록(LocalSystem, `delayed-auto`) — **부팅 시 자동 실행**
  - 데이터 폴더 `%ProgramData%\MCP Monitor` 생성(처음부터 보호된 ACL, 상위 폴더·링크 검사 — Plan 5 리뷰 수정과 같은 규칙), 감사 정책·레지스트리, 선택 시 방화벽(8701)
  - "앱 및 기능" 제거 항목, 시작 메뉴 바로 가기
  - (선택) 로그인 시 트레이 앱 자동 실행 — HKCU `Run`
- 설치 후 시작 메뉴의 **MCP Monitor** → app 모드 창. 창을 닫아도 **서비스는 계속 돕니다**(트레이: 창 열기 / 서비스 상태 / 트레이 종료).
- **패키지 형태 (D2):** A. 자기 설치 exe만 / B. 같은 exe를 감싼 MSI(WiX, `cargo-wix`)도 제공 — GPO·Intune 배포가 필요할 때.

### 4.2 업그레이드
새 버전 exe 실행 → 서비스 정지(`ShutdownSequence`) → 파일 교체 → DB 마이그레이션은 서버가 시작할 때 수행(Plan 5 DB 가드: 더 새 DB 거부) → 서비스 시작. 데이터는 그대로 둡니다.

### 4.3 제거
`mcp-monitor.exe uninstall` 또는 "앱 및 기능" → 서비스 정지·제거 → 감사 정책 복원 → Program Files 제거. 데이터는 `--remove-data`를 줄 때만 지웁니다(지금 `uninstall.ps1 -RemoveData`와 같은 안전장치: 마커 확인, 드라이브 루트·시스템 폴더 거부). 각 사용자의 고지 창 프로필 폴더도 함께 지웁니다.

### 4.4 기능
설치 모드 하나이므로 Plan 1–5의 모든 기능(MCP 감시·자동 복구, 관리 화면·상태 보드, 원격 모드, RDP 세션·Security 로그·명령 수집, 연결마다 고지, 우회 탐지, 로그 조회·보존)을 그대로 제공합니다. 관리 화면은 브라우저 대신 앱 창에서 열리며, 원격 모드(8701)는 지금처럼 다른 PC의 브라우저로 접속합니다.

## 5. 고지 창과 에이전트 (D3)
- **A. 에이전트를 Rust로 옮김 (권장).** 서비스가 `mcp-monitor.exe agent`를 세션마다 띄웁니다. 고지 창은 **최상위 모달 WebView2 창**(작업 표시줄 숨김, 닫기 버튼 없음, '확인'만), 창 이벤트·유휴 수집은 `windows-rs`(SetWinEventHook, GetLastInputInfo)로 옮깁니다. 서버와의 통신 규약(토큰 + HMAC 서버 증명, `/api/agent/*`)은 그대로 → 서버는 바뀌지 않습니다. Plan 4 V3 대체가 없어지고 spec §5.5와 일치합니다.
- **B. 지금 Python 에이전트 유지.** 바꿀 것이 적지만 고지 창은 계속 Edge `--app`입니다.

## 6. 보안·배포 고려
- **코드 서명:** 서명 없는 exe는 스마트 앱 컨트롤·Defender에 막힐 수 있습니다. Authenticode 인증서(예: Azure Trusted Signing)로 `mcp-monitor.exe`와 내장 서버 exe 모두 서명합니다.
- 내장 payload는 Program Files로만 풀고(사용자가 쓸 수 없는 위치), 실행 전 해시를 검증합니다. 공유 `%TEMP%`에는 실행 파일을 두지 않습니다.
- exe 매니페스트는 `asInvoker`로 두고, 설치·업그레이드·제거할 때만 승격해 다시 실행합니다.
- WebView2 창은 `http://127.0.0.1:8700`만 열도록 탐색을 제한하고(다른 주소는 기본 브라우저로), 릴리스 빌드에서 개발자 도구를 끕니다.
- 자동 업데이트는 범위 밖(런타임 외부 네트워크 금지, S4). 업그레이드는 새 exe를 실행합니다.

## 7. 구현 범위 (Plan 6 초안)
1. Rust 작업 공간 `desktop/` (Tauri 2), 빌드에 payload 내장(`build.ps1` 결과를 zstd로 묶어 `include_bytes!`), 서명 단계
2. 모드 판별(설치 여부·버전 비교)·단일 인스턴스·설치 안내 화면
3. 설치·업그레이드·제거를 Rust로 이식 (`install.ps1`/`uninstall.ps1`/`audit-policy.ps1`의 검사·ACL·감사 정책 규칙 그대로, 같은 테스트 시나리오, `--dry-run`)
4. 트레이·창·로그인 시 자동 실행 옵션
5. (D3=A) Rust 에이전트: 고지 모달 WebView2, 창 이벤트·유휴, 서버 규약 호환 테스트
6. E2E(설치 `--dry-run`, app 모드 창이 관리 화면을 여는지), Win 11 Pro 실기기 점검표 추가
- 개발 PC가 Win 11 Home이라 서비스·SYSTEM·RDP 관련은 지금처럼 가짜 객체 테스트 + 실기기 점검표로 남습니다.
