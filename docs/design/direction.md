# 디자인 방향 — MCP Monitor 웹 UI

Task 6 산출물. `frontend-design` 스킬로 정하고, audit-suite의 `emil-design-engineering`·`web-design-guidelines` 규칙으로 점검했습니다. 토큰의 실제 값은 `web/src/styles/tokens.css`, 컴포넌트 규칙은 `docs/design/design-system.md`에 있습니다.

## 1. 대상과 일

- **무엇:** 공유 Windows PC 한 대에서 도는 MCP 서버들의 상태를 감시하고 조치하는 콘솔. 원격 데스크톱 세션은 감사 기록 대상입니다.
- **누가:** MCP 개발자(자기 MCP를 고치고 다시 띄움), Admin(사용자·설정·고지 관리), 그리고 로그인하지 않은 동료(보드만 봄).
- **첫째 일:** "지금 망가진 게 있나, 누가 접속해 있나"를 한눈에 답하는 것. 관리 화면의 일은 그다음 단계(원인 확인, 설정 수정, 수동 조치)를 빠르게 하는 것.

## 2. 콘셉트: 고성능 HMI 관제 콘솔

산업 제어실의 **High-Performance HMI**(ISA-101) 관례를 웹으로 옮깁니다.

1. **색은 상태에만 씁니다.** 화면에 색이 보이면 그것은 언제나 MCP 상태입니다. 버튼·링크·선택 표시·포커스는 색상(hue)이 아니라 **명도**로 강조합니다(주 버튼 = 반전 채움).
2. **정상은 조용하게, 비정상은 크게.** HEALTHY 카드는 중립 패널에 작은 초록 아이콘만 둡니다. 문제가 있는 카드만 상단 3px 상태 띠, 상태 색 스파크라인, 배지 채움을 얻습니다. 그래서 문제가 저절로 눈에 띕니다.
3. **상태는 색 + 아이콘 + 글자.** 색만으로 구분하지 않습니다(WCAG 1.4.1).
4. **보드는 멀리서, 관리는 촘촘하게.** 같은 토큰, 두 가지 밀도.

### 한 군데에 쓰는 대담함

보드 맨 위의 **판정 문장**("MCP 2개에 문제가 있어요" / "모든 MCP가 정상이에요")이 이 제품의 얼굴입니다. 큰 숫자 + 작은 라벨이 아니라, 방 건너편에서 읽히는 한 문장이 가장 나쁜 상태의 `-fg` 색으로 표시됩니다. 그 밖의 요소는 조용하고 규율 있게 둡니다.

### 템플릿 기본값을 쓰지 않은 근거 (한 줄씩)

| 흔한 기본값 | 이 계획의 선택 |
|---|---|
| 보라/파랑 그라데이션 강조 | 브랜드 색 없음. 그라데이션 없음. 강조는 반전 채움(`accent` = fg 명도). |
| 거의 검정(#0B0B0B) 배경 + 형광 강조 하나 | 차가운 강철색 중립(hue 255, L 0.205)의 어두운 회색. 형광 강조 대신 상태 6색만. |
| 모든 것이 같은 둥근 카드 + 같은 회색 그림자 | 반경은 위계(3·4·6·10px, 원형은 점·스위치만). 다크에서 카드는 그림자 없이 헤어라인 테두리. 그림자는 떠 있는 층(메뉴·대화상자·토스트)에만. |
| 모든 라벨 위의 대문자 eyebrow, 가운데 점(·)으로 잇는 메타 | 없음. 메타는 `dl`/열로 나눔. 한국어 라벨은 문장형. |
| 작은 데이터 라벨에 모노 글꼴 | 모노는 **복사·대조하는 기계 값**에만(호스트:포트, IP, sha, 스크립트 본문, run id). 숫자 지표는 Pretendard `tabular-nums`. |
| 섹션마다 fade-up, 카드마다 hover 애니메이션 | 움직임은 상태 변화를 알릴 때와 사용자 조작에 답할 때만(§6). |
| 버튼 문구 끝의 `→` | 없음. 버튼은 동작 이름(“MCP 삭제”, “인증 코드 받기”). |
| 가운데 정렬 대화상자 | 왼쪽 정렬. 콘솔은 읽는 방향이 한 방향입니다. |

## 3. 색 역할

값은 `tokens.css`(OKLCH 원색 → `light-dark()` 역할 토큰). 대비는 `tokens.contrast.test.ts`가 두 테마에서 검사합니다.

| 역할 | 쓰임 |
|---|---|
| `bg` / `surface` / `surface-raised` / `sunken` | 페이지 / 패널·카드 / 떠 있는 층(메뉴·대화상자) / 읽기 전용 입력·코드 |
| `border` | 장식용 헤어라인(내용 묶기). 일부러 조용함 — 3:1 대상 아님(preflight F27) |
| `border-strong` | 의미 있는 경계: 입력칸, 스위치 꺼짐 트랙, outline 버튼. 모든 면 대비 3:1 이상 |
| `fg` / `fg-muted` | 본문 / 보조 텍스트. 모든 면 대비 4.5:1 이상 |
| `accent` / `accent-fg` | 주 버튼·켜진 스위치(반전 채움) |
| `hover` / `selected` | fg를 7%·11% 섞은 반투명 — 어떤 면 위에서도 같은 느낌 |
| `focus` | 2px 포커스 링(회색 계열, 상태 색과 혼동 없음) |
| `danger` / `danger-fg` | 파괴적 동작 버튼, 필드 오류 글자 |
| `scrim` | 모달 뒤 막 |
| `state-{healthy,suspect,action,recovering,failed,maintenance}` | 아이콘·선·띠(3:1) |
| `state-*-fg` / `state-*-soft` | 배지 글자(4.5:1) / 배지·카드 채움(`color-mix(… 18%, transparent)`) |

상태 색상: 정상 green(152), 이상 감지 amber(85), 조치 중 orange(52), 복구 중 cyan(212), 실패 red(22), 점검 중 slate(255, 채도 낮음). 라이트 테마에서는 같은 hue를 어둡게(600), 다크에서는 밝게(400) 씁니다. 모든 값은 sRGB 안에 있습니다(테스트), 그래서 Chromium 123·Firefox 128·Safari 17.5가 같은 색을 칠합니다.

다크 우선: 디자인·검토는 다크에서 먼저 하고 라이트를 맞춥니다. 기본값은 OS 설정 따르기(`color-scheme: light dark`), 사용자는 `ThemeToggle`로 고정할 수 있습니다(Windows 한국어 용어 "어둡게/밝게").

## 4. 유형 척도

글꼴: **Pretendard Variable**(UI 전체) + **JetBrains Mono Variable**(기계 값). npm 패키지에서 번들, CDN 없음, `font-display: swap`. Pretendard는 unicode-range 92개 분할이라 화면에 나온 한글 블록만 내려받습니다.

| 토큰 | 크기 / 행간 | 쓰임 |
|---|---|---|
| `text-xs` | 12 / 18px | 표 머리, 보조 메타, 배지 |
| `text-sm` | 14 / 22px | **관리 본문 기본**, 컨트롤 |
| `text-base` | 16 / 26px | 읽는 글(고지 본문), 터치 입력 |
| `text-lg` | 18 / 28px | 카드 이름, 대화상자 제목 |
| `text-xl` | 22 / 30px | 페이지 제목 |
| `text-2xl` | 28 / 36px | 대시보드 요약 수 |
| `text-metric` | 28→40px 유동, 1.05, -0.02em | 보드 지연·가동률 숫자 |
| `text-display` | 32→56px 유동, 1.12, -0.025em | 보드 판정 문장 |

규칙: 비율 약 1.2(관리). 한글은 라틴보다 행간을 넉넉히(본문 1.57). 큰 글자일수록 자간을 좁힘. 굵기 400/500/600/700만, hover·선택에서 굵기를 바꾸지 않음(레이아웃 흔들림). 바뀌는 숫자는 `tabular-nums`. 한국어 줄바꿈은 어절 단위(`word-break: keep-all`), 제목은 `text-wrap: balance`, 문단은 `pretty`. 한 줄은 80자 미만(`--size-prose: 40rem`).

## 5. 레이아웃 원칙

모든 내용은 왼쪽 정렬, 4px 격자(`--spacing`).

**보드** (익명 첫 화면, 멀리서 읽힘)

```
┌ 상단 바(sticky, 스크롤하면 그림자) ─────────────────────────────┐
│ MCP Monitor  [로컬 관리 모드]          ● 실시간  ◐  [로그인]   │
└──────────────────────────────────────────────────────────────────┘
  ● 접속 중 · 사용자 카드…                      ← 세션 배너(Plan 4)
  MCP 2개에 문제가 있어요                       ← 판정 문장(display)

┌━━ 실패 ━━━━━━━━┐┌━━ 이상 감지 ━━━━┐┌ 정상 ──────────┐
│ calculator  [⊗실패]││ weather [⚠이상감지]││ files    [✓정상]│ ← 이름 행
│ 127.0.0.1:9101     ││ 127.0.0.1:9102    ││ 127.0.0.1:9103  │
│ 지연 —   가동 91.2%││ 지연 842  가동 99.1││ 지연 12  가동 100│ ← 지표 행
│ ╱╲╱╲ (상태 색)     ││ ╱╲╱ ▓▓▓▓░ 23초     ││ ╱╲╱ (회색)       │ ← 스파크라인/게이지
│ 마지막 점검 14:02  ││ …                  ││ …               │ ← 바닥 행
└────────────────────┘└────────────────────┘└─────────────────┘
```

- 그리드: `repeat(auto-fill, minmax(var(--size-board-card), 1fr))`, 정렬은 심각도순(U17).
- 카드 행(이름·지표·스파크라인·바닥)은 **subgrid**로 줄을 맞춰, 이름이 두 줄이 되어도 지표가 한 높이에 섭니다. subgrid가 없으면 일반 grid.
- 카드 내부 배치는 **컨테이너 쿼리**: 좁은 카드는 지표를 세로로 쌓고, 넓은 카드는 나란히.
- `.card:has([data-state=FAILED])`로 띠·테두리를 바꿉니다(JS 없이). 미지원이면 효과만 빠짐.

**관리** (고밀도)

```
┌ 상단 바 ─────────────────────────────────────────────────────────┐
├──────────────┬───────────────────────────────────────────────────┤
│ 대시보드     │ MCP                                   [MCP 등록]  │
│ MCP          │ ┌ 상태 ─ 이름 ─ 호스트:포트 ─ 지연 ─ 가동률 ─ 조치 ┐│
│ 세션 (예정)  │ │ ⊗실패  calc   127.0.0.1:9101   —    91.2  ▶↻■  ││
│ 로그 (예정)  │ │ …   36px 행, 애니메이션 없음                     ││
│ 사용자       │ └──────────────────────────────────────────────────┘│
│ 사전 고지    │                                                   │
│ 설정         │  폼은 --size-prose 폭, 라벨 위·도움말 아래·오류 바로 아래 │
└──────────────┴───────────────────────────────────────────────────┘
```

- 사이드바 `--size-sidebar`(15rem), 컨트롤 높이 36px(`--size-control`), 터치 기기에서는 44px.
- 권한이 없는 메뉴·버튼도 숨기지 않고 `aria-disabled` + 이유 툴팁(U26).

## 6. 모션 원칙

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--motion-fast` | 120ms | hover·press 피드백, 배지 크로스페이드, 메뉴·툴팁 |
| `--motion-base` | 200ms | 대화상자(막과 패널을 같은 시간·이징으로), 토스트, admin 라우트 크로스페이드 |
| `--motion-slow` | 360ms | 고지 다이얼로그 진입, 보드 카드 재정렬 — 드물게 보는 것만 |
| `--ease-out` | cubic-bezier(.23,1,.32,1) | 들어오고 나가는 것 |
| `--ease-in-out` | cubic-bezier(.77,0,.175,1) | 화면 위에서 움직이는 것(카드 재정렬) |
| `--ease-hover` | ease | 색·투명도 피드백 |

- `transform`/`opacity`만 움직입니다. 예외는 U25 하나(OTP 원형 타이머 `@property --progress`).
- 사용자가 하루 수백 번 보는 것(표 행, 내비 전환, 메뉴 hover)은 움직이지 않거나 120ms 이하.
- 저절로 움직이는 것은 상태 변화를 알릴 때만: 접속 중 펄스, 복구 중 회전 테두리, 이상 감지 카운트다운 게이지.
- 진입은 `scale(0.95)`+투명도에서 시작(0에서 시작하지 않음). 버튼 누름은 `scale(0.98)`.
- 테마를 바꾸는 순간에는 모든 전환을 끕니다(`[data-theme-switching]`, 약 50ms).
- `prefers-reduced-motion: reduce`: CSS 애니메이션·전환·View Transition 전부 끔(`base.css`), Motion은 `MotionConfig reducedMotion="user"`. 움직이는 요소는 `data-anim`으로 표시해 E2E가 찾습니다.
- 표(이력·조치·사용자)에는 애니메이션이 없습니다. 행 hover 색 전환도 없습니다.

## 7. 최신 CSS 사용 지도 (확정)

| 기능 | 쓰는 곳 | 대체(미지원) |
|---|---|---|
| OKLCH + `color-mix()` + `light-dark()` | 모든 색 토큰 | (목표 브라우저 기준 필수) |
| Cascade Layers, Nesting | `base.css`, 컴포넌트 CSS | 필수 |
| Container Queries | `McpCard`·`SessionCard` 내부 배치 | 필수 |
| `:has()` | 카드 상태 테두리(`.card:has([data-state=FAILED])`), 폼 오류 행 강조 | 효과만 빠짐 |
| Subgrid | 보드 카드의 행(이름·지표·스파크라인) 정렬 | 일반 grid |
| View Transitions | admin 라우트 전환(`defaultViewTransition`) | 즉시 전환 |
| Scroll-driven Animations | 상단 바 그림자 | 그림자 고정 |
| `@starting-style` | 고지 다이얼로그·팝오버 진입 | 진입 효과 없음 |
| `@property` | `--gauge-from`(`<number>`, 카운트다운 시작 비율), `--progress`(재발송 원형 타이머, U25) | 정적 표시 |
| Popover + Anchor Positioning | 보드 스파크라인 값 툴팁(`popover="hint"` + `anchor-name`) | 카드 하단 고정 표시 |
| `text-wrap: balance` | 제목·빈 상태 문구 | 일반 줄바꿈 |
| `prefers-reduced-motion` | 전역 | — |

구현 메모:
- 레이어 순서 `tokens, theme, base, components, utilities`는 `app.css` 첫 줄에서 정합니다(Tailwind의 레이어 선언보다 먼저 나와야 `tokens`가 가장 낮은 우선순위가 됨). 빌드 결과에서 확인했습니다.
- 상단 바 그림자는 `box-shadow`를 움직이지 않고, 그림자를 가진 가상 요소의 `opacity`를 스크롤 타임라인에 묶습니다(`transform/opacity만` 규칙 유지).
- `*-soft`는 `color-mix(in oklch, var(--color-state-x) 18%, transparent)`로 `light-dark()` 값을 다시 섞습니다. 목표 브라우저 최신판에서 동작하며, 대비 테스트는 이 값을 면 위에 합성해 계산합니다.
- `@property`·Popover·`@starting-style`는 그 기능을 쓰는 과제(8·9·14)가 자기 CSS에서 선언합니다.

## 8. 문구의 목소리

`design:ux-copy` 결과(`web/src/copy/ko.ts`). UI는 해요체, 짧고 능동형, 사과·느낌표 없음, 오류는 "무슨 일 + 어떻게 하면 되는지". 사전 고지만 공식 안내문이라 합니다체. 자세한 규칙은 `design-system.md`의 "문구".
