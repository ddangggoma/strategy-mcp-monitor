# Plan 3 — Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 지금 백엔드가 가진 기능 전부의 웹 UI를 만듭니다. 익명 상태 보드, 이메일 + OTP 로그인, 관리 셸(채널 배지·역할), 대시보드, MCP 목록·상세(설정, 스크립트 조회·편집, 버전·되돌리기, 이력·지연 차트, 수동 조치 토스트, 점검 모드, 소유권 이전, 등록·삭제), 사용자 관리, 전역 설정(로그 보존 포함), 그리고 사전 고지 메시지의 저장소·API·편집기(§5.5 편집 부분)입니다. RDP 세션 수집·고지 표시는 Plan 4, 로그 조회는 Plan 5의 몫입니다.

**Architecture:** `web/`는 Vite 다중 엔트리(`board`·`admin`·`notice`) React 19 앱입니다. 세 번들은 `web/src/lib/`(API 클라이언트, fetch 기반 SSE 클라이언트, 보드 상태 저장소, 권한 미러)와 `web/src/components/`를 공유합니다. 빌드 산출물(`web/dist`)은 사전 압축(br/gz)된 해시 파일이고, FastAPI가 두 채널 모두에서 정적 라우트로 제공합니다(`/` = 보드, `/admin/*` = 관리 SPA, `/notice` = 고지 단독 페이지). 서버는 UI에 필요한 작은 보강(채널별 쿠키 이름, `me.otp_provider`, 사용자 요약 필드, 대시보드용 최근 활동, 보존 미리보기, 고지 저장소)만 추가합니다. 권한 판단은 서버가 최종이고, 클라이언트는 같은 규칙 표(JSON, 서버 테스트로 동기화 검증)로 "비활성 + 이유"를 미리 보여줍니다.

**Tech Stack:** Node 26 LTS(≥ 26.13.0), pnpm, React 19, TypeScript(strict), Vite, Tailwind CSS v4, shadcn/ui(Radix), Motion, Lucide, Recharts, TanStack Query·Router·Table, react-hook-form + zod, CodeMirror 6, Sonner, cmdk, date-fns, jsdiff(`diff`), Pretendard Variable + JetBrains Mono(로컬 번들), Vitest + Testing Library + MSW, Playwright + `@axe-core/playwright`. 서버: Python 3.15, FastAPI, uv, pytest.

**Spec:** `docs/PLAN.md` (v0.5). 이 계획은 §6(화면, §6.5 디자인 시스템), §7 프런트 성능 목표, §4 권한·채널의 UI 표시(§4.4 "숨기지 않고 비활성 + 이유"), §8 API, §9.1 Node·pnpm 정책, §5.5 고지 **편집** 부분, §5.6 보존 미리보기, §11 P3 완료 기준("외부 채널·비소유자의 스크립트 편집 불가 시연")을 구현합니다. 이전 계획에서 넘어온 항목은 `docs/superpowers/plans/carry-forward.md`의 "Plan 3" 두 절이며, 모두 아래 과제에 배정했습니다(Task 16에서 체크). 이미 내려진 결정은 `2026-11-04-plan1-rulings.md`, `2026-11-05-plan2-rulings.md`에 있습니다. 이 계획의 결정(U1–U32)은 **부록 A**, 서버 API와 클라이언트 함수·Query key 대응은 **부록 B**에 있습니다. 본문의 `U<n>`은 부록 A의 행입니다.

## Review Focus

1. **편집 중 세션 만료(30분 유휴·8시간 최대·역할 변경으로 세션 폐기)**: 스크립트·고지 편집기에서 저장하면 401이 옵니다. 다시 로그인한 뒤 같은 화면으로 돌아오고, 입력한 내용이 남아 있어야 합니다. → Task 12 `restores the script draft after re-login`, `a 401 on save keeps the draft and sends the user to login with this page as redirect`, Task 9 `logs in with email then OTP, restarts the stream and returns to the redirect target`
2. **같은 채널의 다른 탭에서 다시 로그인한 경우**(이전 세션 폐기 → 이 탭의 CSRF 토큰이 낡음): 첫 변경 요청이 403 `csrf`를 받으면 `/api/auth/me`로 토큰을 다시 받아 **한 번만** 재시도해야 하고, 무한 반복하면 안 됩니다. → Task 7 `retries once after a csrf refresh`, `does not loop on repeated csrf`
3. **수동 조치 대기 중 SSE가 끊기는 경우**(서버 재시작, 절전 복귀, 슬롯 경쟁의 빈 200, 429 `Retry-After`): 보드는 백오프로 다시 연결하고, 대기 중인 토스트는 이력 조회로 결과를 찾아 끝나야 합니다. → Task 7 `reconnects after an empty 200 with backoff`, `honors Retry-After on 429`, Task 10 `reconciles a pending action from history after reconnect`
4. **설정 폼을 고치는 중에 실시간 갱신이 오는 경우**(다른 사람의 수정, 수동 종료로 `maintenance`가 바뀜): 사용자가 고친 필드는 덮어쓰지 않고, 고치지 않은 필드만 새 값으로 바뀌며, 저장은 바뀐 필드만 보내야 합니다. → Task 11 `live update keeps dirty fields`, `PUT sends only dirty fields`
5. **원격 모드에서 Local 전용 화면 주소를 직접 여는 경우**(`/admin/users`, `/admin/settings`, `/admin/notice`, `/admin/mcps/new`): 빈 화면이나 "찾을 수 없음"이 아니라 "로컬 관리 모드에서만" 이유를 보여주고, Local 전용 API를 호출하지 않아야 합니다. → Task 13 `local-only pages on external explain and make no request`, Task 14 `notice editor on external explains and makes no request`, Task 12 `create page on external explains and makes no request`
